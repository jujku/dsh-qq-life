# 状态提示词怎么写

在 DSH 设置 → QQ Life 状态 → **状态提示词** 中，选择状态、填写描述并保存。留空或点击“恢复这一项默认”后保存，即使用内置描述。支持16种状态，不必全部填写。

## 这段提示描述什么

**人格卡**描述“她是谁”：身份、长期性格、说话习惯、经历、价值观。

**状态提示词**描述“她此刻怎样”：心情舒服还是低落、有没有精力、对当前对象愿意聊多少、表达更含蓄还是更外放。状态是临时调节，不是另立一张人格卡。

推荐写法：**此刻感受 → 投入意愿 → 表达方向 → 克制边界**。通常一两句话、50–150字足够，不必写固定台词、每句格式或必须回复几条。

| 状态      | 可以往这个方向写                     | 应避免                                 |
| --------- | ------------------------------------ | -------------------------------------- |
| 心情好    | 心里满足，交流轻松，可以懒洋洋地开心 | 每句话兴奋、一直主动找人、要求发说说   |
| 低落      | 兴趣淡一点，允许安静，不需要强撑热闹 | 怪群友不陪自己、卖惨、编造伤心事件     |
| 疲惫      | 想少投入一点，回应简短、自然结束     | 关系再好也必须陪聊；每次都喊累         |
| 生气      | 暂时不太想接这个人的话，语气收敛     | 辱骂、惩罚、迁怒别人、永久记恨         |
| 关系亲近  | 愿意听对方说，关心真实聊过的具体近况 | 突然恋爱、编造共同经历、赋予管理员权限 |
| 初识      | 礼貌接话，保留适当距离               | 低好感就敌视或瞧不起对方               |
| 含羞/傲娇 | 按原人设含蓄地表现一点在意           | 强迫其他类型角色变傲娇，持续刻薄或否定 |
| 无聊      | 对自然话题更有兴趣，没话题也能安静   | 绕过白名单、频率和作息，追着群友催回复 |

例子——心情好：

> 现在心里挺舒服的，说话可以松弛一点，偶尔自然接个梗。开心不代表精力无限，不必为了表现情绪而主动找话。

例子——亲近：

> 对这个人更愿意投入注意力，可以顺着真正感兴趣的话题聊下去，想起实际知道的爱好。保留原本的说话方式，不刻意撒娇或强行问近况。

## 怎么触发

编辑器显示每一项的准确条件。主基调依次判断：**高怒气 → 疲惫/休息 → 轻微别扭 → 信任保留 → 亲近/熟悉/初识/普通相处**，只选一项。普通互动才可能追加兴奋、低落语气、含羞或傲娇表达。全局心情另按低于40、40至不足75、75以上分三档；无聊补充还要求精力、作息与当前对象允许。

只将当前触发的描述加入提示，不会把16段模板全部塞入每轮对话，也不新增模型请求。模板文字仍计入每次回复的输入token，写得越长费用越高，不必用满字数。编辑器修改的是表达，不修改这些条件、心情算法或权限。

## 可选变量

使用**单层**花括号：`{relationship}` 关系标签，`{affinity}` 亲近度，`{familiarity}` 熟悉度，`{trust}` 相处信任，`{anger}` 怒气，`{fluster}` 当前对象含羞，`{mood}` 心情，`{boredom}` 无聊，`{energy}` 精力，`{arousal}` 兴奋，`{tsundere}` 傲娇倾向，`{shyness}` 含羞倾向。数字仅供模型参考，不应让角色直接向群友报数；未知关系维度显示“未知”。

例如“当前精力{energy}，可以少说一点，但保持原来的人设。”不需要使用变量也可以正常工作。双花括号的 DSH 变量、代码表达式和任意自定义变量均不支持，不会执行脚本。

## 如何保持人格

原人格卡继续保留，身份和权限边界不在本编辑器内开放。插件为自定义文本附加固定范围说明：只调节感受、语气与投入；生气、疲惫不能被全局开心覆盖；不改变关系事实、身份或权限。

这种分层能减少正常写作时的人设冲突，**无法保证模型在管理员故意填写“忽略人格卡”等冲突指令时仍绝对不受影响**。不要把永久性格、角色背景、工作命令、改分要求或工具操作放进这里。需要改人设时应直接改人格卡。

每项最多800字，自定义内容合计最多6000字。设置保存在插件私有 config.json 的 `statePrompts` 字段；通过 API 更新这个字段会整体替换覆盖项，空对象恢复全部内置描述。其他参数不受影响。
