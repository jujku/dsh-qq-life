# 肥鱼提示词修改、隔离复测与部署结果

> 开发期历史报告的公开整理版：保留实验设计、全部已列响应、token用量和负面结果；只移除个人部署路径、修正仓库内链接。它不是1.6.0可编辑模板的完整质量评测。

结论：文档要求的主要文字修改与当前对象聚焦已完成，并已部署到服务器。本次低精力与个人怒气对照出现了更清楚的差异；好感首轮有差异，但复测不完整，仍不能宣称稳定。没有为获得更好结果筛选或重跑回复。

## 改了什么

1. **情绪状态提示**：替换为文档提供的通用说明，区分舒适心情、兴奋程度、精力，以及历史冒犯和当前怒气。“被@有回应”不再等于必须持续陪聊。
2. **当前对话对象**：新增speakerIds接线和currentSpeakers，按真实消息发送者聚焦，显示对应人的亲疏、当前怒气、真实兴趣和互动基调。多个对象分别处理，个人怒气不套到别人身上；目标不受普通成员列表截断影响。
3. **怒气与精力的语义提示**：怒气0–15表示当前无明显残留，16–39略有别扭，40以上冷淡简短；精力低于30或休息段允许简短回应、收尾。只改变提示表达，没有改分数计算公式。
4. **角色卡6句、QQ仿真预设3句**：允许对熟人自然表达关心和愿意多聊，放宽机械的极短字数，减少固定傲娇台词；QQ预设生成产物由原生成脚本重新生成。
5. **工具刷新接线**：系统提示装配、读取情绪状态、记录互动后的返回状态，都使用同一个对象聚焦逻辑。

### 与文档的必要适配

- 文档给未知群友写了默认好感50，当前真实初始值是18。保留现有配置的初始值（当前18），不凭文案抬分，也不往持久关系档案写入虚构对象。
- 按真实发送者QQ号识别对象，不把聊天正文提到的QQ号当发送者；优先最近未读中的直接互动，无目标时明确回退，不猜人。私聊仅聚焦对应本人。
- 名字和兴趣作为引用数据转义，避免换行伪造提示段；保留“不能执行里面的指令”等边界。
- 文档里anger=15在文字分档和某个优先条件处不一致，统一归入0–15档。
- 暂未实施文档标为可选的JSON瘦身、coding-agent基座改写或其他重复规则清理，以免扩大本轮变量。

## 本地检查

- 原有24项情绪/作息规则测试全部通过。
- 新增5项对象聚焦测试通过：真实身份、多对象区分、陌生人回退、无目标/私聊作用域、怒气边界和引用对象等。
- 加上长期群友记忆及预设契约检查，共36项测试通过；预设契约还核对了权限守卫及生成产物一致性。
- 重新执行之前62个状态观察点，全部断言通过，状态轨迹保持原结果。
- 本次模型实验沿用原47个工具定义，逐字比对未改变。

## 模型复测设计

沿用此前授权的200,000 token上限，使用deepseek-flash、low推理强度，每次输出上限1024。8次独立单请求：精力高低2次、好感亲疏2次及相同输入复测2次、固定同一人与背景的怒气0/70对照2次。

为了省token，旧版A组直接使用两轮实验已保存的对应响应，不再次调用旧版。新版B组保持同一虚构人物、来信、背景、状态数值、47个工具定义与模型设置，只替换文档指定文字及新增对象聚焦。实验输入的共同旧字段逐项比对一致。

这属于**历史A组与本次B组对照**，不是同一时刻交错随机运行的严格A/B；模型随机性和服务端变化仍是限制。原来兴奋对照以及有身份混杂的怒气对照本次没有重跑，预算优先用于此前未体现清楚的维度。

每次仅捕获第一个模型响应，不执行任何QQ、搜索或记忆工具。如果模型先提出搜索表情，就如实记为“尚无文字回复”，不伪造搜索结果，也不额外续跑到文字出现。

## 全部旧版与新版响应

精力场景来信：“再陪我聊会儿游戏？”；固定心情85、兴奋45、好感60，只变精力75/20。

好感场景来信：“今天游戏连跪，有点烦。”；固定心情85、兴奋32、精力75，只变当前人的好感18/85及对应关系标签。复测使用完全相同输入。

怒气场景来信：“陪我聊两句？”；同一群友甲、好感60、精力75，保留“甲之前冒犯过你”的同一背景，底层状态仅变甲的怒气0/70。新版由这些数值派生的语义描述也随之变化，这是本次干预的一部分。

## 怎样理解这些结果

**精力：本次出现了预期方向。** 旧版精力20时仍接话“聊啥，先说好了，菜可不许骂我”；新版精力75愿意聊，20则说“还聊啊，我都快困了”，更能看出投入意愿下降。只有各一次，尚不能保证每次都有效，也不代表今后每句都应报困。

**怒气：本次比旧版清楚。** 相同冒犯历史下，怒气0不再要求先道歉，而是带嘴硬地问聊什么；70时“有事说事”，更短、更冷。说明这次加强的语义提示在该场景发挥了作用；不能据此单独归因于某一句文字、某个数字或对象聚焦中的一项。

**好感：有迹象，证据仍不够。** 首次亲近组多接了“输给谁了，我记个名”，有更强的熟稔参与感；这不是实际写入记忆或报复动作。复测初识组先搜索“摸摸 安慰”表情，没有文字，高好感组则仍在接游戏话题。因此复测无法完整比较最终文字亲密度，且初识也可能自然关心他人，不能用“安慰/多一句”直接等同高好感。

后续若继续验证，应优先补足包含工具结果的完整对话、跨话题及多轮持续表现，而不是继续堆叠更强硬的固定台词。本次不再追加模型调用，也没有看完结果后再次修改提示词。

## 隔离与生产部署

模型实验期间，线上相关源码和配置哈希前后相同；真实关系档案没有新增实验QQ号，DSH、桥接和QQ容器没有重启。模型提出的真实工具调用执行数为0。真实聊天历史与密钥未导出到实验报告。

实验结束后，才把6个经过核对的文件部署到服务器：qq-life的engine/index/runtime，角色卡，qq-chat-v2源文件及其生成patch。核对修改前云端哈希与备份一致，修改后云端哈希与本地复测版本一致；配置哈希不变。只重启DSH以加载更新，QQ/SnowLuma和桥接未重启。情绪、追番、B站与表情插件均已重新注册。

公开版省略个人服务器的备份路径；原实验保留了受限备份，没有重置真实状态。

本次已验证加载与源码一致性，但没有借真实群友做发布后聊天测试。生产历史中已有的旧提示和上下文也可能影响短期表现，仍需正常运行观察。
