# QQ Life · 肥鱼状态

给 DSH 里的 QQ 群友增加持续的**情绪、精力、群友关系和个人长期记忆**。状态会转成当前会话的提示，让同一个角色面对熟人、陌生人、冒犯或疲惫时有不同的投入和语气。

这是从自用“肥鱼状态”整理出的 **qq-bridge 扩展插件**，可单独下载安装，不替换角色卡。**使用前必须已经搭好 DSH＋qq-bridge，并能在 qq-bridge 二代仿真模式下正常收发 QQ 消息。** 本插件在此基础上增加状态与关系，不提供 QQ 登录或独立机器人服务。

目前只适配 **qq-bridge 的会话数据和接口**。仅安装 DSH、dsh-im 或其他 OneBot 通道，不能直接使用本版；其他通道的接入属于后续适配工作。

## 有什么

- 心情、无聊、兴奋和精力随真实互动与时间变化；高心情不等于持续亢奋。
- 同一个 QQ 跨群共用亲近、熟悉和相处信任；有效交往需要真实回复回执，连续消息合并，防止刷分。
- 对具体人的怒气和含羞独立；私聊不影响全局心情、无聊和群聊冷落计时。
- 记录群友本人公开自述的爱好、学习和习惯；按当前话题与亲近程度选资料注入提示，支持纠正、删除。
- 可选主动找熟人聊天，遵守白名单、作息、冷却、配额和未回应退避。
- DSH 设置内的管理页，查看状态、变化原因、群友关系与资料。
- 16种状态的提示词可分别编辑，附带触发条件、写作方向、可选变量和恢复默认。只描述当前感受与投入，保留原人格卡，详见 [状态提示词写法](docs/STATE_PROMPTS.md)。

普通情绪、关系计分和资料检索使用本地规则，**不额外逐条调用模型**。回复本身仍由原会话的模型生成，表现是提示引导，不保证每个分数都有固定台词。

## 安装前

请先按 qq-bridge 自己的说明完成接入，并确认机器人原有回复正常，再安装本插件。它不会替你补齐桥接、QQ登录或会话权限配置。

- Node.js **22.13+**。
- 已安装并能启动的 DSH。本版适配开发时使用的 **DSH 0.2.0-rc.2** 宿主接口；其他版本需自行验证。
- [qq-bridge](https://github.com/Derpyu520/qq-bridge) 的二代仿真模式（`reserved2`），有效白名单、角色和现有 QQ 会话。需要其 `state/social-v2.json`、`state/sessions.json` 等运行文件和 `/api/socialV2/wake` 接口。
- 插件与桥接位于同一文件系统，且可通过回环地址访问桥接控制接口。Docker 中需共享桥接配置/状态卷和插件数据卷；分容器时要保证回环访问可达。

无需安装 qq-leisure、B站插件、dsh-meme 或额外数据库，也无需往插件里填写 API Key。

## 下载后安装

从 [GitHub 仓库](https://github.com/jujku/dsh-qq-life) 的 Code → Download ZIP 下载源码并解压到长期保留的位置，也可以在 [Release 下载页](https://github.com/jujku/dsh-qq-life/releases/latest) 下载并解压 `qq-life-1.6.0.tgz`，进入其中的 `package` 文件夹。不要把目录留在临时下载缓存里。

先停止 DSH。打开终端，进入插件目录。下面的路径是示例，需要换成自己的：

```powershell
node scripts/install.mjs --bridge-root "D:/apps/qq-bridge" --profile-dir "D:/apps/dsh-home/profiles/web"
```

上面只预览，不写文件。确认目录正确后，再执行：

```powershell
node scripts/install.mjs --bridge-root "D:/apps/qq-bridge" --profile-dir "D:/apps/dsh-home/profiles/web" --apply
```

Linux 同样使用 `node scripts/install.mjs`，将路径改为自己的绝对路径。安装工具备份 profile 的 `package.json`，只添加本地依赖、bundle 和目录链接，不修改桥接的白名单或模型配置。

**DSH_HOME 必须与启动 DSH 时一致。** 未设置时，默认数据目录是用户主目录下的 `.dsh/qq-life`。使用自定义 `--data-dir` 时，必须先设置并长期保留 `QQ_LIFE_DATA_DIR`。详细说明见 [安装和迁移](docs/INSTALL.md)。

重启 DSH，在 **设置 → QQ Life 状态** 查看面板。修改“角色称呼”为自己的唤醒名字；“仅匹配角色名”留空时使用桥接当前角色，填写后只对同名角色生效。

## 首次配置

1. 检查桥接当前角色、二代模式和白名单，先确认原来的 QQ 对话正常。
2. 设置起床/休息时间，默认 `10:00–23:30`，使用 **UTC+8**，暂不支持跨午夜作息。
3. 主动聊天默认关闭。想开启时，先填写允许主动聊天的群号，再开启开关；还必须在桥接白名单中。
4. 模型整理资料默认关闭。本地明确自述提取和资料检索仍然工作。开启后使用 DSH 已配置的 provider/model，默认 `deepseek-official / deepseek-flash`；请填写自己实际可用的 ID。

额外模型整理按批次限频：每人至少间隔2小时、每天最多2次，全局每天最多8次，每次最多900输出 token；输入用量另计，不是固定每日 token 总预算。默认在工作日 UTC+8 `09–12、14–18` 暂停，周末不暂停。这是插件的保守时间规则，**不代表模型提供方当前计价承诺**。

可选 qq-leisure 联动关闭时完全不读取其存档；开启后只读同一 DSH_HOME 下 `qq-leisure` 的作息、学习完成回执和专注状态。看番、说说、B站登录等不属于本插件。

## 工具和权限

只添加 `qq_life_state`、`qq_life_observe` 两个会话工具，不给群友文件、命令执行或管理权限。`qq_life_observe` 要求真实 messageId 和逐字证据，身份、白名单和会话范围仍由桥接核对。

原版 qq-chat-v2 如果有工具白名单，需管理员把这两个名字加入允许名单；仍然保留原有危险工具限制。不要为了本插件放开全部工具。提示词中也应允许模型在有语义判断需要时使用它们，示例见 [提示词接入](docs/PROMPTS.md)。

管理页保留本地同源限制，使用 DSH 原有登录保护。云服务器建议通过 SSH 隧道以 localhost 访问；不支持直接把此管理页暴露为公开群友页面。

## 数据与升级

插件只在自己的数据目录保存 `connection.json`、`config.json`、`state.json`、`state.json.prev` 和 `person-memory.json`。这些可能包含群号、QQ号、昵称和原文证据，**不要上传到 GitHub**。

公开群聊的本人资料会跨群用于本人；私聊不进入公开长期资料，语义整理会把待整理的公开原文发送给所选模型提供方。启用前应按使用场景向参与者说明，管理员可查看、纠正和删除资料。详见 [数据说明](docs/DATA.md)。

自用1.4版可在停机备份后迁移，状态 version 2 / 资料 version 1 保持兼容。不要让新旧两个插件同时写同一份数据。具体步骤见 [安装和迁移](docs/INSTALL.md)。

## 开发期实验与效果边界

以下是开发过程中实际进行的隔离实验。保留首次结果，也保留未达到预期和无法完整比较的结果；没有为挑好看的回复反复重跑。完整报告已整理为公开版，放在本仓库内，链接不依赖开发者本地目录。

|阶段|实验内容|模型请求 / 实际token|主要结果与完整报告|
|---|---|---|---|
|第一轮|兴奋32/80、精力75/20对照；62个离线状态观察点|4次 / **93,696**|兴奋有一次可见差异，低精力语气未达预期。[第一轮报告](docs/experiments/01-emotion-baseline.md)|
|第二轮|初识/亲近首次与复核、冒犯者/旁人、固定背景只变怒气|8次 / **188,177**|好感差异未稳定复现；怒气对照暴露历史背景混杂。[后续报告](docs/experiments/02-relationship-anger.md)|
|提示词修改后复测|加强当前对象聚焦与状态语义，复用旧版结果作对照|8次 / **193,724**|低精力与怒气在该场景更清楚；好感复测一项先搜索表情、未生成文字，仍不能宣称稳定。[复测报告](docs/experiments/03-prompt-retest.md)|
|关系规则升级|成功回复回执、连续交往合并、跨群防刷、道歉/信任、资料检索与删除|0次真实模型请求|历史联合检查100项通过，模拟输入与语义标签由夹具提供；不能冒充语言效果实验。[规则验证](docs/experiments/04-relationship-rules.md)|

前三轮合计 **20次真实模型请求、475,597 token**。模型为 `deepseek-flash`、推理强度 `low`，使用开发时的完整固定提示、角色卡和47个工具声明；人物与聊天为虚构，模型提出的工具调用只捕获意图，**没有向真实QQ发消息或执行真实会话工具**。缓存输入计入总token，用量不是费用，也不是插件单独增加的token开销。

![历史规则模拟：情绪衰减、防刷、消气和夜间恢复](docs/experiments/images/emotion-trajectories.png)

这些结果需要按以下限制理解：

- **规则正确与语言有效是两件事。** 计分、去重、隔离和阈值可离线验证；模型是否稳定表现出亲疏，仍受角色卡、话题、上下文与随机性影响。
- **是历史版本实验，不是1.6.0全功能评测。** 复测同时改过配套角色卡、QQ预设与插件状态提示，不能把整体变化归因于本插件一项；本发布包也不包含那次全部配套修改。
- **不是线上历史逐字重放。** 使用一致的提示构造与工具定义，聊天和成员均为虚构；复测的旧版组来自之前保存的响应，未做同一时刻的随机交错A/B。
- **样本少、存在不完整输出。** 兴奋、精力和怒气样本不足以证明普遍稳定，好感证据尤其有限；不能据此宣传“好感分数必然决定回复效果”。
- **可编辑模板尚无付费模型质量复测。** 1.6.0已在Windows/Linux通过同一套54项离线测试，并验证编辑器保存、刷新保留和恢复默认；这不等于每位使用者自定义的提示词都已验证有效。

## 开发与验证

从源代码仓库运行，无需 `npm install`：

```sh
npm test
npm run check
npm pack
```

测试只使用临时目录、虚构人物与假模型，不发真实 QQ 消息。包内不含 node_modules、运行存档或凭据。更详细的算法见 [关系和记忆](docs/RELATIONSHIPS.md)，维护入口见 [架构](docs/ARCHITECTURE.md)。
